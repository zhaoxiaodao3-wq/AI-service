4. 实现短期上下文拼接与 Token 截断策略（手动实现，练手核心）。
5. 完整 Demo：可多轮连续对话、切换模型、异常有提示。

## 5. 详细任务分解

### 5.1 统一模型适配器（S1-01）

在 `backend/app/adapters/model_adapter.py` 实现：

- `chat(request: ChatRequest) -> ChatResponse`：非流式对话。
- `stream_chat(request: ChatRequest) -> AsyncIterator[str]`：流式对话，逐段产出文本增量。
- 统一入参 `ChatRequest`（model/messages/temperature）与出参 `ChatResponse`（content/usage）。
- 统一异常 `ModelError`，包含 `code`（如 `invalid_key`、`insufficient_quota`、`timeout`、`stream_broken`）与用户可读 `message`。
- LiteLLM 调用：`litellm.acompletion`（非流式）与 `litellm.acompletion(stream=True)`（流式）。
- 官方/中转切换：根据配置选择 base_url 与 api_key；`LLM_PROXY_*` 有值时优先走中转。

### 5.2 模型配置与列表接口（S1-02）

- `.env` 新增/启用：`LLM_PROVIDER`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_PROXY_BASE_URL`、`LLM_PROXY_API_KEY`。
- 预置模型清单（config 中定义）：
  - OpenAI：`gpt-4o`、`gpt-4o-mini`
  - DeepSeek：`deepseek-chat`
  - Claude：`claude-3-5-sonnet-20241022`
- `GET /api/models`：返回当前模式（官方/中转）、可用模型列表、当前默认模型。
- 模型切换由前端传 `model` 参数，不持久化（阶段 2 再入库）。

### 5.3 SSE 流式对话接口（S1-03）

- `POST /api/chat/stream`，请求体：`{ messages: [...], model?: string }`。
- 响应 `Content-Type: text/event-stream`，每条事件格式：

  ```text
  data: {"type":"delta","content":"你"}
  data: {"type":"delta","content":"好"}
  data: {"type":"done","usage":{...}}
  data: {"type":"error","code":"invalid_key","message":"API Key 无效"}
  ```

- 逐段 `yield` 模型增量；完成时发 `done`；异常时发 `error` 并结束流。
- 前端能通过代理（Vite `/api`）正常接收 SSE。

### 5.4 短期上下文与 Token 截断（S1-04）

- 服务层新增 `context_builder.py`：
  - 接收 `messages`（前端传的当前会话消息，阶段 2 前由前端维护）。
  - 手动估算 token：优先 tiktoken；不可用时用「中文字符数 + 英文单词数」估算函数。
  - 若估算超过 `MAX_CONTEXT_TOKENS`（默认 4000，可配置），从最早的非系统消息开始删除，直到满足上限。
  - 系统提示词（system prompt）始终保留，不参与截断。
- 将截断后的消息传给 ModelAdapter。

### 5.5 前端聊天页真实对接（S1-05）

- 聊天页移除静态占位，改为真实交互：
  - 消息列表：用户消息 + AI 消息，AI 回复期间显示「正在思考…」。
  - 输入框发送后立即追加用户消息并调用 `/api/chat/stream`。
  - 流式渲染：解析 SSE 事件，`delta` 增量追加到 AI 消息，实现打字效果。
  - 模型下拉：调用 `GET /api/models` 展示可选模型，切换后作为参数发送。
  - `error` 事件：停止流并显示友好错误。
- `request.ts` 保持统一请求封装；SSE 调用可单独封装 `chatStream` 函数。

### 5.6 异常容错（S1-06）

| 场景 | 捕获方式 | 用户提示 |
|------|----------|----------|
| Key 失效/未配置 | 请求前校验 + LiteLLM 异常 | 请检查 API Key 配置 |
| 额度不足 | LiteLLM 异常 code 映射 | 账户额度不足，请稍后重试 |
| 请求超时 | httpx/timeout 异常 | 模型响应超时，请重试 |
| 中转断流 | 流中断/解码异常 | 连接中断，请重新发送 |
| 未知错误 | 兜底 | 服务器内部错误，请稍后重试 |

所有异常统一在适配层映射为 `ModelError`，接口层转成 SSE `error` 事件或统一 JSON 错误。

**页面布局：** 整体模仿豆包网页版：

```text
┌────────────┬──────────────────────────────┐
│  左侧菜单    │       右侧聊天区域              │
│  + 新会话    │   ［消息列表］                │
│  历史会话    │                              │
│  · 会话1    │  ┌────────────────────────┐  │

└────────────┴──────────────────────────────┘
```

- 左侧菜单只有两项功能：`新会话` 按钮与 `历史会话` 列表。
- 点击 `新会话`：清空当前聊天区，新建一个会话并加入历史列表。
- 点击历史会话：切换到对应会话的历史消息。
- 阶段 1 会话仅存前端内存，刷新页面丢失；阶段 2 持久化到 PostgreSQL。
- 右侧为聊天区域：消息列表 + 底部输入区。
- 输入框左侧有「上传文件」「上传图片」按钮：
  - 上传后以附件卡片/缩略图显示在输入区上方。
  - 发送时附件随消息携带（消息结构含 `attachments` 字段）。
  - 阶段 1 只做上传与展示，不做解析；文件解析属于阶段 3，图片多模态理解后续阶段接入。

## 8. 风险与避坑

| 风险 | 对策 |
|------|------|
| 没有可用 Key | 先实现并自测错误分支；有 Key 后补真实流式验证 |
| 中转服务断流/限速 | 适配层捕获断流并重连一次或友好报错 |
| Token 估算不准 | 估算函数保守（多估），宁可多截断不可溢出 |
| SSE 被代理缓冲 | Vite 代理对 `text/event-stream` 不缓存；后端禁用响应缓冲 |
| 模型名不兼容 | 统一走 LiteLLM 的模型名，Claude 用 Anthropic 规范名 |
| 密钥泄露 | Key 只放 `.env`，不上传 Git |
