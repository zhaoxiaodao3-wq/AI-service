# 阶段十二可观测性与工程化部署 · 原始需求

## 需求来源

`docs/roadmap/阶段7-13增强路线图.md` 阶段 12「可观测性与工程化部署」，结合用户诉求：

> 「阶段12能否进行 CI 部署，希望能优化一下任务，能用 AI 完成的部署就 AI 完成，不能就写明操作步骤给我去操作」

## 原始需求（roadmap）

1. Alembic 迁移替代 `create_all`，支持表结构升级。
2. OpenTelemetry 全链路 Trace：HTTP → RAG → LLM → PG/Qdrant → 工具。
3. Trace 接入 Grafana Tempo/Loki，与日志关联。
4. CI/CD：测试 → 构建 → 镜像推送 → 部署。
5. 生产部署文档：云数据库、HTTPS、备份恢复、资源限制。

## 任务分工原则（用户明确要求）

| 分工 | 内容 |
|------|------|
| **AI 完成** | 全部代码与配置：Alembic 迁移、OTel 埋点、CI 流水线文件、生产编排（docker-compose.prod.yml）、备份/恢复脚本、部署文档 |
| **用户操作** | 需要外部账号/凭证/真实执行的部分：GitHub 仓库与 Secrets、云服务器、域名、执行部署脚本、Docker 重建验证 |

## 验收标准（roadmap）

- 数据库可迁移升级（Alembic upgrade/downgrade 可用）。
- 一次请求能看到完整 Trace 瀑布（Tempo 中可见 HTTP → RAG → LLM → DB 链路）。
- CI 全绿可一键部署（流水线配置就绪，用户推送后自动执行）。
