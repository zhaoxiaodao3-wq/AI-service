# 阶段二：业务数据全持久化

## 原始需求

按照全阶段落地手册阶段 2 的要求，把会话、消息、模型配置、用户全部落到 PostgreSQL：

1. 用户表：账号、密码（哈希）、创建时间。
2. AI 模型配置表：模型名称、厂商、启用状态、API Key（加密存储）、BaseURL、权重。
3. 会话表：会话 ID、用户 ID、所选模型、会话标题、创建时间。
4. 消息表：归属会话、角色、内容、Token 消耗、创建时间。
5. 业务接口：
   - 会话：新建、删除、切换、重命名、查询历史会话。
   - 消息：保存每轮对话、查询会话历史消息。
   - 模型：动态加载可用模型，前端下拉切换。
6. 安全：数据库中的 API Key 必须加密存储，禁止明文。
7. 前端：刷新页面不丢失历史会话；聊天页会话列表、历史消息来自后端。
8. 不引入登录鉴权（阶段 5 再做），默认本地用户。
