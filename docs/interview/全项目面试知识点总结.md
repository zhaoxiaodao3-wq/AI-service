# AIGC 对话 + RAG + AI 记忆 · 面试知识点总结

> 覆盖已实现阶段 0-8 及全部补充。后续阶段（9-13）在文末标注“规划中”，不算已实现能力。

## 一、项目一句话介绍

一个基于 FastAPI + Vue3 的 AIGC 对话平台：统一多模型接入、SSE 流式打字机、会话/文档/模型配置持久化、手写 RAG 知识库问答、AI 跨会话长期记忆，并配套 JWT 认证、Agent 工具调用、Loki+Grafana 观测与 Docker 一键部署。

## 二、技术栈与架构

```text
浏览器
  │ Nginx 容器（SPA + /api 代理，SSE 关闭缓冲）
  ▼
FastAPI 后端
  ├── LiteLLM 适配层（多模型/官方/中转）
  ├── RAG（解析→切片→Embedding→Qdrant→检索→Prompt）
  ├── Agent 工具调用（Function Calling）
  ├── PostgreSQL（用户/会话/消息/文档/模型配置/刷新令牌/调用统计）
  ├── Qdrant（document_vectors / memory_vectors）
  ├── Redis 规划中（阶段 10/11）
  └── Loki + Promtail + Grafana（日志观测）
```

## 三、阶段知识点清单

### 阶段 0：环境搭建与架构初始化

核心知识点：

- FastAPI 分层：`api / core / db / models / schemas / services / repositories / adapters / utils`
- 为什么分层：路由只做 HTTP，服务管业务，仓库管 SQL，适配器管外部模型
- Docker Compose：PostgreSQL + Qdrant，端口映射、健康检查、数据卷
- 环境配置：`.env` / `pydantic-settings`，开发/生产分离
- Qdrant 集合：`document_vectors`、`memory_vectors`，向量维度与距离算法（Cosine）
- Vue3 + Vite + TypeScript + Element Plus + Vue Router + axios
- CORS 与 Vite `/api` 代理

高频追问：

- 为什么数据库和向量库分开？业务数据在 PG，语义检索在 Qdrant，职责不同
- 健康检查为什么数据库挂了也返回 200？探活字段返回 `error`，服务本身仍可诊断

### 阶段 1：基础对话 + 多模型 + 短期记忆

核心知识点：

- LiteLLM 二次封装：统一 `ChatRequest / ChatResponse`，不裸调
- 官方直连 vs 第三方中转：`_resolve_credentials` 优先级切换，只改 `.env`
- 异常统一映射：`ModelError`（invalid_key / insufficient_quota / timeout / stream_broken）
- SSE 流式：`text/event-stream`，`data:` 事件，`delta/done/error`
- 短期上下文：历史消息拼接 + Token 截断（删最早消息、保留 system）
- 前端打字机：SSE 分片入缓冲区，定时器逐段追加；Vue 必须操作**响应式代理对象**，否则页面不更新
- 日志：FastAPI ASGI 中间件记录 request start/body/end；SSE 逐段 `chat_stream delta`
- 观测：Promtail 尾随 Docker stdout → Loki → Grafana Live Tail

高频追问：

- SSE 和 WebSocket 区别？SSE 单向服务端推送、自动重连、HTTP 兼容；WebSocket 双向
- 打字机为什么之前出现“空白”？直接修改 push 前的原始对象，Vue 追踪不到
- Token 截断为什么删最早消息而不是中间？短期记忆按时间顺序，旧信息优先级低

### 阶段 2：业务数据全持久化

核心知识点：

- SQLAlchemy ORM：`User / AiModel / ChatSession / ChatMessage / Document / ModelCall / RefreshToken`
- 外键、`relationship`、`cascade="all, delete-orphan"`、`ondelete=CASCADE`
- `Base.metadata.create_all` + 幂等种子（默认用户、模型）
- Fernet 对称加密：API Key 密文落库，`SECRET_KEY` 管理
- Repository/Service/API 分层 + FastAPI `Depends(get_db)` 依赖注入
- 统一响应 `{code, message, data}`，`AppError` + 全局异常处理
- 聊天自动持久化：SSE 流结束 `finally` 写 user/assistant 消息

高频追问：

- `create_all` 为什么不适合生产？不能增量迁移，需 Alembic（阶段 12 规划）
- 为什么 API Key 要加密而不是哈希？调用时需要解密还原，属于可逆敏感数据

### 阶段 3：自建 Qdrant + 完整 RAG

核心知识点：

- RAG 五步：文档解析 → 切片 → Embedding → 入库 → 检索 → Prompt → 生成
- 文件解析：TXT/MD 直接读，PDF 用 `pypdf`，仅支持文字层
- 切片：`chunk_size=500 / chunk_overlap=50`，固定窗口 + 步长重叠
- Embedding：`EMBEDDING_MODE=api`（SiliconFlow `BAAI/bge-m3`，1024 维）；`local` 哈希向量仅开发兜底
- Qdrant：PointStruct、UUID 点 ID、payload（doc_id/user_id/text/chunk_index）、Filter 按 user_id 过滤、TopK + score_threshold
- 检索：余弦相似度、阈值降噪
- Prompt 组装：系统提示词只依据资料回答，资料不足如实说明
- 前端：上传页、知识库开关、文档列表/删除

高频追问：

- 为什么用 1024 维？取决于 Embedding 模型输出，Qdrant 集合维度必须一致
- 相似度阈值怎么调？先看真实 score 分布，再定阈值
- 切片为什么要有重叠？防止跨片段语义被切断
- RAG 怎么防止幻觉？限定“只依据资料”，且资料不足要说明

### 阶段 4：AI 长期向量记忆

核心知识点：

- 每轮对话结束生成记忆文本：`用户：...\nAI：...`，向量化写入 `memory_vectors`
- 记忆召回：问题向量化 → 按 user_id 过滤 → `exclude_session_id` 排除当前会话 → TopK + 阈值
- 双层记忆融合：长期记忆 + 短期上下文 + 知识库片段（可选）+ 新问题
- payload 记录 `user_id/session_id/text/type=memory`
- 记忆写入失败仅 warning，不影响聊天

高频追问：

- 为什么排除当前会话？短期上下文已经覆盖本轮，避免重复注入
- 记忆精度不如知识库？语义召回，重要事实建议放知识库

### 阶段 5：工程化完善

核心知识点：

- 模型配置化：从 `ai_models` 表读取 provider/BaseURL/加密 Key，无配置回退 `.env`
- 流式重试：未输出 delta 时重试，已输出不重试，避免重复内容
- 限流：ASGI 中间件，按 IP 滑动窗口，默认 30 次/分，超限 429
- 调用统计：`model_calls` 表（model/session/success/token/duration），`GET /api/stats`

高频追问：

- 限流为什么用滑动窗口？比固定窗口更平滑，能防突发
- 流式重试为什么输出后不重试？重试会造成重复文本
- 分布式限流怎么做？规划中，用 Redis 滑动窗口（阶段 11）

### 阶段 6：容器化部署与 UI 收尾

核心知识点：

- 前端多阶段 Dockerfile：Node 构建 → Nginx 托管 `dist`
- Nginx：`/api` 代理到 backend，`proxy_buffering off` 保证 SSE 逐字输出，SPA `try_files`
- 健康检查：backend 请求 `/api/health`，frontend wget 首页
- `docker-compose.yml` 通过 `include` 合并观测栈与工具
- Loki + Promtail + Grafana 实时观测；Adminer / Qdrant Dashboard 可视化
- 二次元卡通 UI：CSS 变量 + Claymorphism（厚边框/圆角/双层阴影）
- 聊天布局：输入框固定底部、消息区独立滚动、回底按钮

高频追问：

- 为什么 Nginx 要 `proxy_buffering off`？否则 SSE 会被缓冲成一次性返回
- 容器健康检查有什么用？编排器知道服务是否 ready
- `create_all` 与迁移的关系？规划 Alembic（阶段 12）

### 阶段 7：用户认证与多租户

核心知识点：

- JWT：Header.Payload.Signature，`sub` + `exp`，无状态
- bcrypt：自动加盐哈希，`checkpw` 校验
- 刷新令牌：只存 SHA-256 哈希，支持轮换与撤销（`refresh_tokens` 表）
- 认证依赖：`get_current_user` 从 Bearer Token 解析用户
- 多租户：会话/文档/记忆全部按 `user_id` 过滤，越权返回 404
- 前端：登录页、路由守卫、axios 拦截器携带 Token、401 跳登录
- 踩坑：SSE 聊天用原生 fetch，不走 axios，必须显式加 Authorization
- 迁移脚本：`migrate_local_data.py` 把 local 用户数据迁到新用户

高频追问：

- JWT 和 Session 区别？JWT 无状态、可跨服务；Session 服务端存储、易撤销
- 刷新令牌为什么存哈希？即使库泄露，原 token 也无法直接使用
- 登出为什么不能只清前端？要撤销服务端 refresh token
- 多租户怎么防越权？所有查询都带 user_id，返回 404 不暴露存在性

### 阶段 8：Agent 工具调用

核心知识点：

- Function Calling：模型返回 `tool_calls`，执行后把 `role: tool` 消息回填
- 工具注册中心：name / description / JSON Schema / handler
- 内置工具：时间、计算器（AST 安全求值）、知识库检索、文档列表、天气、汇率
- Agent 循环：最多 3 轮，工具结果回填后再问模型
- SSE 事件：`tool_start` / `tool_done`
- 免费外部 API：wttr.in（天气）、open.er-api.com（汇率）
- 安全：不用 `eval()`，AST 白名单求值；用户数据工具必须带 user_id

高频追问：

- Function Calling 和 Prompt 里“假装调用工具”区别？真实执行 + 结果回填，可验证可追踪
- Agent 循环为什么设最大轮数？防止死循环与成本失控
- 工具执行安全边界？参数校验、AST 白名单、超时、结果截断

## 四、高频面试题速答

### 1. 为什么用 SSE 而不用 WebSocket？

AI 对话是“服务端 → 浏览器”单向流，SSE 更简单、原生支持重连、走 HTTP 兼容性好；WebSocket 适合双向实时（协同编辑、游戏）。

### 2. RAG 的核心链路是什么？

```text
文档解析 → 切片 → Embedding → Qdrant 入库 → 问题向量化 → 相似度检索 → RAG Prompt → 模型回答
```

### 3. 怎么减少 RAG 幻觉？

- 只依据检索片段回答
- 相似度阈值过滤无关片段
- 资料不足时明确说明
- 后续规划：Rerank、引用溯源（阶段 9）

### 4. 向量检索为什么可能不准？

- Embedding 模型质量
- 切片策略（大小/重叠）
- TopK 与阈值
- 关键词/专有名词丢失 → 后续混合检索（阶段 9）

### 5. JWT 泄露怎么办？

- 缩短 access token 有效期
- refresh token 服务端可撤销
- 生产建议 HttpOnly Cookie + 刷新轮换

### 6. 流式输出怎么保证前端不卡？

- fetch + ReadableStream 解析 SSE
- 打字机缓冲区 + 定时器
- 操作响应式代理对象
