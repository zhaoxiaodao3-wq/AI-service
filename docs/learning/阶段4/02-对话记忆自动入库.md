# 02 · 对话记忆自动入库

## 做了什么

聊天流带 `session_id` 结束时，后端自动生成记忆文本并写入 Qdrant：

```text
用户：<最后一条用户消息>
AI：<完整回答或错误文案>
```

payload 包含 `user_id`、`session_id`、`text`、`type=memory`。

## 为什么

如果让前端手动保存记忆，容易漏存或重复存。放在聊天流 `finally` 里，和消息持久化同一时机执行，用户无感知，一次对话结束记忆自动产生。

## 原理

### 写入时机

```python
# chat.py event_stream 的 finally
message_service.add_message(db, session_id, "assistant", saved_text)
memory_text = f"用户：{last_user_full}\nAI：{saved_text}"
memory_vector = (await embed_texts([memory_text]))[0]
vector_repo.upsert_memory(user_id, session_id, memory_text, memory_vector)
```

### 为什么在 finally

正常结束、模型报错、未知异常都会走到 `finally`，确保只要有过对话就能尽量留下记忆。记忆写入失败只记 warning，不会让聊天接口报错。

### 向量 ID

用 `memory-{session_id}-{text前64字符}` 生成稳定 UUID，同一轮重复写入时 ID 可预测。

## 命令解释

```powershell
Invoke-RestMethod -Uri http://localhost:6333/collections/memory_vectors/points/scroll -Method Post -ContentType "application/json" -Body '{"limit":5,"with_payload":true}'
```

查看已写入的记忆文本。

## 避坑

- 只有带 `session_id` 的聊天才会写记忆；不传 session_id 保持阶段 1 纯流式行为。
- 用户消息为空（只传附件）时不写记忆。
- 记忆写入使用 Embedding 接口，网络异常时由 try/except 兜住，不影响聊天结果。
