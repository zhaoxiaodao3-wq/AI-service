# 03 · 跨会话检索与降噪

## 做了什么

新提问时，后端把问题向量化后在 `memory_vectors` 中检索：

- 只检索当前用户的记忆。
- 默认排除当前会话（`exclude_session_id`），避免把本轮短期上下文重复注入。
- `MEMORY_TOP_K=3` 限制召回数量。
- `MEMORY_SCORE_THRESHOLD=0.35` 过滤低相似度记忆。

## 为什么

长期记忆要“精准召回”，不是把所有历史都塞进去。排除当前会话是为了避免重复；阈值过滤是为了降噪，防止无关历史把回答带偏。

## 原理

```text
问题 → Embedding → Qdrant search
  filter: user_id = 1, must_not session_id = 当前会话
  limit: memory_top_k
  score_threshold: memory_score_threshold
```

召回结果 payload 里的 `text` 会被拼进系统提示词的“历史记忆（跨会话）”部分。

## 命令解释

```powershell
$body = '{"messages":[{"role":"user","content":"我叫什么名字？"}],"model":"glm-4-flash","session_id":7}'
Invoke-RestMethod -Uri http://localhost:8000/api/chat/stream -Method Post -ContentType "application/json" -Body $body
```

新会话提问，后端会自动召回历史记忆。

## 避坑

- 阈值设太高会“想不起来”，设太低会“乱想”，建议先跑几次真实检索看 score。
- 记忆检索和知识库检索是两套集合、两套参数，互不影响。
- 当前会话记忆会在本会话后续提问时被短期上下文覆盖，所以排除当前会话是合理默认。
