# 01 · 模型响应缓存

## 做了什么

普通聊天按“模型 + 问题哈希”缓存回答到 Redis，默认 TTL 1 小时；相同问题再次提问直接返回缓存。

## 为什么

模型调用有成本与延迟，热点问题缓存后响应更快、更省钱。

## 原理

```text
key = chat:{model}:{sha256(question)}
GET 命中 → 直接返回
未命中 → 调用模型 → 保存回答
```

## 命令解释

```powershell
docker exec aigc-redis redis-cli --scan --pattern "chat:*"
```

## 避坑

- RAG/工具问题不缓存，避免上下文错乱。
- key 必须带模型名。
- TTL 太短没意义，太长信息过期。
