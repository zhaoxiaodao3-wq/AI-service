# 09 · 阶段1补充对后续阶段影响

## 结论

阶段1补充（豆包风格 UI、请求/响应日志、SSE 逐段日志、Loki+Grafana 观测栈、backend 容器化）**不会阻塞阶段 2-6**，但会缩减阶段 5 和阶段 6 的部分任务范围，阶段 2/3 需要继承已有 UI 与容器化基础。

## 分阶段影响

| 阶段 | 影响 | 需要做的调整 |
|------|------|--------------|
| 2 业务数据全持久化 | 无阻塞；前端已换成豆包风格 UI | 会话/消息从内存态改为数据库加载，页面沿用现有布局 |
| 3 自建 Qdrant + RAG | 无阻塞；backend/Qdrant 已容器化，上传页 UI 已就绪 | 上传页继续沿用现有风格；新增文件解析、切片、向量化、检索、Prompt 组装 |
| 4 AI 长期向量记忆 | 无直接影响 | 在已有 `memory_vectors` 集合上实现记忆写入与召回 |
| 5 工程化完善 | 日志基础已被阶段1提前完成 | 补 Token/调用统计、成功率、限流重试、日志采样与保留策略；Loki/Grafana 作为观测底座 |
| 6 容器化部署 + 收尾 | 后端/PostgreSQL/Qdrant/Loki/Promtail/Grafana 已容器化并一键启动 | 剩余：前端静态资源容器化、生产级健康检查/资源限制/日志保留、最终部署与简历收尾 |

## 已就绪的基础

- 后端请求/响应日志：`request start/body/end`，含 status、duration、body 摘要。
- SSE 逐段日志：`chat_stream delta` 实时输出，`chat_stream finish` 完整汇总。
- 实时观测：Loki + Promtail + Grafana，浏览器 Explore → Live Tail。
- 一键启动：`docker compose up -d --build` 启动 6 个容器。
- 前端：豆包风格浅色 UI + 打字机流式效果 + 移动端侧栏自适应。

## 后续阶段的落地顺序建议

阶段 2 直接开始即可；阶段 5 做统计与容错时把 Loki 查询作为数据来源之一；阶段 6 不再从零写编排，改为“补前端容器 + 生产化配置 + 收尾”。
