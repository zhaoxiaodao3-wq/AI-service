# 06 · 前后端如何联调

## 这一步做了什么

完成了前端的基础工程设施：

- `src/api/request.ts`：统一 axios 请求封装（baseURL、超时、错误提示、Token 预留）
- `src/router/index.ts`：路由配置（`/`、`/chat`、`/upload`）
- `src/layouts/MainLayout.vue`：全局布局（顶部导航 + 内容区）
- 三个基础页面：首页、聊天页、文档上传页
- 验证：`pnpm build` 类型检查通过，三个路由均返回 200，`/api` 代理到后端健康检查成功

## 为什么要这么做

### 1. 请求封装为什么统一

如果每个页面自己写 `fetch`，将来要加 Token、改超时、统一错误弹窗，就要改几十个地方。统一封装后，这些能力只写一次，所有接口自动生效。

### 2. 路由为什么需要

聊天页、文档上传页是不同的功能页面。路由把「地址栏 URL」和「页面组件」绑定，用户点导航就切换页面，还能在阶段 2 加路由守卫（未登录跳登录页）。

### 3. 布局为什么抽出来

三个页面都共用顶部导航，如果把导航写进每个页面，改一处要改三处。抽成 `MainLayout` 后，页面只关心自己的内容。

## 底层原理

### HTTP 与 JSON

前端和后端是两个独立程序，通过 HTTP 通信：

```text
前端（5173） ──HTTP 请求──> 后端（8000）
前端（5173） <──JSON 响应── 后端（8000）
```

请求格式一般是：

```text
POST /api/chat
Content-Type: application/json

{ "model": "gpt-4o", "messages": [...] }
```

### axios 拦截器

```ts
request.interceptors.request.use((config) => config)
request.interceptors.response.use(...)
```

拦截器就像「快递中转站」：请求发出前统一贴标签（Token），响应回来前统一拆包装（错误提示），页面代码就不用关心这些公共逻辑。

### Vite 代理 `/api`

```ts
proxy: {
  '/api': { target: 'http://localhost:8000', changeOrigin: true }
}
```

浏览器访问 `http://localhost:5173/api/health` 时，Vite 开发服务器把请求转发给 `http://localhost:8000/api/health`，再原样把响应拿回来。对浏览器来说请求始终来自 5173，所以没有跨域问题。

### SPA 路由刷新

`createWebHistory` 是 HTML5 History 模式：地址栏显示 `/chat` 而不是 `/#/chat`。开发环境 Vite 会自动把未知路径回退到 `index.html`，所以直接刷新 `/chat` 也能打开页面。

## 关键命令逐条解释

| 命令 | 含义 |
|------|------|
| `pnpm dev` | 启动前端开发服务器（5173） |
| `pnpm build` | 类型检查 + 生产打包（输出到 dist/） |
| `pnpm add 包名` | 安装前端依赖 |
| 访问 `http://localhost:5173/api/health` | 验证代理链路是否通 |

## 常见问题与避坑

1. **页面 404**：确认路由 path 与菜单 index 一致，且页面文件在 `src/views/`。
2. **代理 502/500**：后端没启动，或 `vite.config.ts` target 端口写错。
3. **改代码不生效**：Vite 热更新一般即时生效，偶尔改配置类文件需要重启 `pnpm dev`。
4. **打包体积大**：Element Plus 是全量引入导致，阶段 5 可改按需引入优化。
