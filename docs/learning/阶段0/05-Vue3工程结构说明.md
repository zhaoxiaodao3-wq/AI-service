# 05 · Vue3 工程结构说明

## 这一步做了什么

在 `frontend/` 目录创建了 Vue3 + TypeScript + Vite 前端工程，并完成基础配置：

- 安装 Element Plus（UI 组件库）、vue-router（路由）、axios（请求）、pinia（状态管理）
- 配置 `vite.config.ts`：开发服务器端口 5173，`/api` 代理到后端 8000
- 配置 `.env.development` / `.env.production` 环境变量
- 验证：前端页面返回 200，`/api/health` 代理到后端返回 200

## 为什么要这么做

### 1. 前后端为什么是两个独立目录

前端和后端语言、运行环境、生命周期完全不同：

| | 前端 | 后端 |
--|------|------|
| 语言 | TypeScript/HTML/CSS | Python |
| 职责 | 展示界面、用户交互 | 业务逻辑、数据、AI 接口 |
| 运行 | 浏览器 / Vite | Python 进程 |

所以 `backend/` 和 `frontend/` 分开，各自维护依赖和启动命令，但同属于 `D:\code\AI-agent` 这个大仓库。

### 2. 为什么用 Vite

Vite 是前端开发服务器 + 打包工具：

- 开发时秒级启动、改代码自动刷新
- 生产时把代码打包成浏览器能直接运行的文件

### 3. 为什么要有环境文件

开发环境要连本地后端，将来生产环境要连线上地址。环境文件按环境切换，代码里不写死地址：

```dotenv
VITE_API_BASE=/api
```

## 底层原理

### SPA（单页应用）

传统网页每次点链接都向服务器要一个新页面；SPA 只加载一个 HTML，页面切换由 JavaScript 在内存里完成，流畅且像原生 App。

Vue Router 负责「地址栏 URL ↔ 页面组件」的映射。

### 组件化

界面拆成一个个组件（`.vue` 文件），每个组件 = 模板 + 逻辑 + 样式：

```vue
<template> 界面长什么样 </template>
<script setup> 逻辑和状态 </script>
<style> 样式 </style>
```

### TypeScript 的作用

给 JavaScript 加类型：变量、函数参数、接口返回值都有类型检查。写代码时就能发现很多低级错误，而不是运行到浏览器才报错。

### Vite 代理 `/api` 的原理

```text
浏览器请求 http://localhost:5173/api/health
  → Vite 开发服务器收到
  → 按规则把 /api 开头转发到 http://localhost:8000/api/health
  → 后端返回 JSON
  → Vite 原样返回给浏览器
```

浏览器认为数据来自同一个地址（5173），所以不触发跨域；后端也不需要单独配置复杂跨域。

### pnpm 与 node_modules

`package.json` 是前端依赖清单，`pnpm install` 按清单下载到 `node_modules`。pnpm 比 npm 快且省磁盘，命令基本一致。

## 关键命令逐条解释

| 命令 | 含义 |
|------|------|
| `pnpm create vite frontend --template vue-ts` | 创建 Vue3 + TS 模板工程 |
| `pnpm install` | 安装 package.json 里的全部依赖 |
| `pnpm add element-plus vue-router axios pinia` | 安装四个常用库并写入 package.json |
| `pnpm dev` | 启动开发服务器（默认 http://localhost:5173） |
| `pnpm build` | 类型检查 + 打包生产文件到 dist/ |

## 常见问题与避坑

1. **前端打不开**：确认在 `frontend/` 目录运行 `pnpm dev`，且 5173 端口没被占用。
2. **`/api` 代理 502**：后端没启动，或 `vite.config.ts` 的 target 端口与后端不一致。
3. **改环境文件不生效**：Vite 只会在启动时读取 `.env*`，改完要重启 `pnpm dev`。
4. **pnpm 提示版本更新**：可忽略，不影响使用。
