# 04 · 聊天流自动持久化与前端历史会话

## 做了什么

1. `ChatStreamRequest` 增加 `session_id`。
2. 前端发送消息时带上当前会话 ID。
3. 后端在流开始前保存用户消息，流结束后保存完整 AI 回复；错误时保存错误文案。
4. 前端挂载时从后端加载会话列表和历史消息，刷新页面不丢失。

## 为什么

如果只提供会话 CRUD，前端还得自己调接口保存每条消息，容易漏存或重复存。把持久化放进聊天流本身，一条 SSE 请求完成后数据库就已经有“用户问题 + AI 回答”两条记录，前端刷新后直接按会话加载，行为自然闭环。

## 原理

### SSE 流里的持久化时机

```text
前端 POST /api/chat/stream (session_id)
  ├─ 流开始前：保存 user 消息
  ├─ 流过程中：每段 delta 实时返回给前端（打字机显示）
  └─ 流结束后：保存 assistant 完整回复
```

后端在 `event_stream()` 里累计 `full_text`，`finally` 块中落库。`finally` 无论正常结束还是发生错误都会执行，保证不漏存。

### 前端加载历史

```ts
// onMounted
const res = await request.get('/sessions')
if (res.data.sessions.length) {
  sessions.value = res.data.sessions.map(...)
  await switchSession(res.data.sessions[0].id)  // 加载第一条会话消息
} else {
  await newSession()
}
```

`switchSession` 调用 `GET /api/sessions/{id}/messages`，把数据库里的消息映射成前端消息结构。

## 命令解释

```powershell
$body = '{"messages":[{"role":"user","content":"你好"}],"model":"glm-4-flash","session_id":1}'
Invoke-RestMethod -Uri http://localhost:8000/api/chat/stream -Method Post -ContentType "application/json" -Body $body
```

带 `session_id` 发起流式对话。完成后：

```powershell
Invoke-RestMethod -Uri http://localhost:8000/api/sessions/1/messages
```

应返回两条消息：`user` 和 `assistant`。

## 避坑

- `switchSession` 里如果先设置 `activeSessionId` 再调用自己，函数开头 `id === activeSessionId` 会直接 return，导致消息没加载；必须先调用，让函数自己设置当前会话。
- 异步生成器的 `finally` 在响应被完整消费后才执行，测试必须读完整个 SSE body 再断言数据库。
- 错误分支只保存错误文案，不保存半截内容，避免把不完整回答当成正常结果。
- 不传 `session_id` 时保持阶段 1 原行为，兼容旧调用与测试。
