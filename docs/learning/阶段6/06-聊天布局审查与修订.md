# 06 · 聊天布局审查与修订

## 做了什么

用 ui-ux-pro-max 审查上一版聊天布局改动，发现“输入框居中”用 `transform: translateY(calc(-50vh + 80px))` 实现，脆弱且违背聊天产品常规。本次修订：

- 输入框始终固定在聊天区底部。
- “今天想聊点什么？”作为消息区空态居中展示。
- 侧栏占满整高，会话列表内部滚动。
- 回底按钮只在不靠底时显示，点击平滑回底。
- 补齐 `aria-label`，尊重 `prefers-reduced-motion`。

## 为什么

聊天产品用户心智是“输入区固定底部”；输入框居中会让人误判可操作区域，且基于 vh 的位移在小屏/缩放下不稳定。审查还指出：固定元素要注意重叠、空态要放在内容区、高频 scroll 要节流、动效要尊重系统偏好。

## 原理

### 标准布局

```css
.layout { height: 100vh; }
.content { flex: 1; min-height: 0; overflow: hidden; }
.chat-page { height: 100%; min-height: 0; overflow: hidden; }
.sidebar { height: 100%; min-height: 0; overflow: hidden; }
.session-list { overflow-y: auto; }
```

侧栏和消息区各自独立滚动，页面不整页滚动。

### 回底按钮

```text
scroll 事件 → requestAnimationFrame 节流
距底部 > 160px 且有消息 → 显示按钮
点击 → scrollTo({ behavior: smooth })
```

`prefers-reduced-motion` 时使用 `auto` 即时滚动。

## 命令解释

```powershell
cd frontend
pnpm build
docker compose up -d --build frontend
```

打开 http://localhost:5173/chat：新会话时提示居中、输入框在底部；发消息后输入框保持底部，滚动回顶会出现回底按钮。

## 避坑

- 不要用 `vh` 硬编码位移模拟“居中输入”，用 flex/grid 布局态。
- 固定元素必须给下方内容留出空间（消息区底部 padding）。
- scroll 回调要节流，避免每帧执行重逻辑。
- 图标按钮必须带可访问名称（`aria-label`/title）。
