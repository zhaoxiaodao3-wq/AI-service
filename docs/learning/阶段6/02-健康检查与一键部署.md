# 02 · 健康检查与一键部署

## 做了什么

- `backend` 增加 healthcheck：容器内请求 `/api/health`。
- `frontend` 增加 healthcheck：Nginx 内请求首页。
- 一条命令启动整套：

```powershell
docker compose up -d --build
```

## 为什么

容器“能启动”不等于“能用”。健康检查让编排器知道服务是否真的 ready，`depends_on` 可以按健康状态启动依赖服务，也方便部署平台自动重启/摘流。

## 原理

```yaml
backend:
  healthcheck:
    test: ["CMD", "python", "-c", "urllib.request.urlopen('http://127.0.0.1:8000/api/health')"]
    interval: 10s

frontend:
  healthcheck:
    test: ["CMD", "wget", "-qO-", "http://127.0.0.1/"]
```

容器状态从 `starting` → `healthy` 才是可用状态。

## 命令解释

```powershell
docker compose up -d --build
docker compose ps
```

`ps` 里所有服务应为 `healthy` 或 `Up`。

## 避坑

- 健康检查间隔不要太短，避免启动期误判失败。
- 生产环境建议由部署平台（K8s/Swarm）接管健康检查。
- 前端健康检查只验证 Nginx 活着，业务可用性仍靠 `/api/health`。
