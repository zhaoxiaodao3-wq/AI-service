# 05 · 聊天布局与滚动交互优化

## 做了什么

聊天页新增三处交互：

1. 左侧操作栏占满整高，会话多时只在侧栏内部滚动。
2. 新会话时输入框在屏幕中央；发送第一条消息后平滑移动到屏幕底部固定。
3. 消息变多时只有聊天区滚动，并在距离底部较远时显示“回到底部”按钮。

## 为什么

聊天产品最核心的体验是“对话流”：新会话时输入框居中更聚焦；开始对话后输入框沉底更符合聊天习惯；消息区独立滚动 + 回底按钮避免长对话时整页乱滚。

## 原理

### 侧栏滚动

```css
.chat-page { height: calc(100vh - 64px); overflow: hidden; }
.sidebar { height: 100%; min-height: 0; overflow: hidden; }
.session-list { overflow-y: auto; min-height: 0; }
```

侧栏外层禁止溢出，只有会话列表区域滚动。

### 输入框居中 → 落底

`centeredInput` 计算属性判断“无消息且未加载”，此时：

```css
.chat-main.centered-input .input-area {
  transform: translateY(calc(-50vh + 80px));
}
```

输入区仍处于底部布局位置，只用 `transform` 上移居中；移除类后平滑回到底部，性能好且不触发重排。

### 回底按钮

监听 `.messages` 的 `scroll`：

```text
距底部 > 160px 且消息数 >= 4 → 显示按钮
点击 → scrollTo({ behavior: 'smooth' }) → 隐藏
```

## 命令解释

```powershell
cd frontend
pnpm build
docker compose up -d --build frontend
```

访问 http://localhost:5173/chat：新开一个会话看输入框居中，发消息看它落到底部。

## 避坑

- 用 `transform` 做居中动画，不要改 `top/height`，否则会重排卡顿。
- 侧栏 `min-height: 0` 必须加，否则 flex 子项不会收缩，内部滚动失效。
- 消息区底部要留 padding，否则最后一条消息会被输入框盖住。
- 回底按钮阈值要体验后调，太早出现会烦人，太晚失去意义。
