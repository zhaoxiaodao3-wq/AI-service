# 01 · 双模式兼容与按模型配置

## 做了什么

阶段 5 让聊天接口按 `ai_models` 表读取模型配置：

- 每个模型可独立配置 `provider`、`base_url`、加密后的 API Key。
- 调用该模型时，先查数据库配置；没有则回退 `.env` 的中转/官方配置。
- 官方直连与第三方中转仍只改 `.env` 即可切换。

## 为什么

之前所有模型共用 `.env` 的一个 Key 和 BaseURL，切模型就要改全局配置。模型表配置化后，不同模型可以用不同厂商、不同 Key、不同中转地址，也更接近生产环境的多模型管理。

## 原理

### 凭证解析优先级

```text
1. ai_models 表里该模型的加密 Key + BaseURL
2. .env 的中转 Key（LLM_PROXY_*）
3. .env 的官方 Key（LLM_API_KEY）
4. 都没有 → invalid_key
```

`model_adapter._resolve_credentials(model_name)` 会在每次调用时查一次数据库，命中模型配置就用解密后的 Key。

### 为什么不用缓存

开发阶段模型配置可能随时改，每次都查库保证“改表即生效”。生产环境可加短 TTL 缓存减少查询。

## 命令解释

```powershell
docker exec aigc-postgres psql -U aigc_user -d aigc_chat -c "SELECT name, provider, base_url FROM ai_models ORDER BY weight;"
```

查看当前模型配置。

## 避坑

- 数据库 Key 必须用 Fernet 密文，`decrypt_secret` 失败时回退 .env，避免单模型配置坏了拖垮全部聊天。
- `.env` 配置作为兜底，不要删掉。
- 中转/官方切换依旧走 `.env`，与数据库配置互不冲突。
