# 03 · 模型调用统计

## 做了什么

新增 `model_calls` 表，记录每次模型调用：

- `session_id`、`model`
- `success`（是否成功）
- `token_count`（估算值）
- `duration_ms`（耗时）
- `created_at`

`GET /api/stats` 返回总次数、成功率、总 Token、按模型分组统计。

## 为什么

没有统计就不知道“模型花了多少钱、失败率高不高”。统计接口可以和 Grafana/Adminer 配合，把调用情况变成可观测数据。

## 原理

### 写入时机

聊天流结束后，在 `chat.py` 的 `finally` 里写入一条 `ModelCall`：

```python
success = counts["error"] == 0
token_count = max(1, len(full_text) // 2)  # 中文估算
duration_ms = int((time.monotonic() - started_at) * 1000)
model_call_repo.create_model_call(db, session_id, model, success, token_count, duration_ms)
```

Token 是“字符数 / 2”的估算值，不是模型返回的精确 usage；阶段 5 之后可换成 tiktoken 精确统计。

## 命令解释

```powershell
Invoke-RestMethod -Uri http://localhost:8000/api/stats
```

返回示例：

```json
{
  "total_calls": 1,
  "success_rate": 1.0,
  "total_tokens": 9,
  "by_model": { "glm-4-flash": { "calls": 1, "success": 1, "tokens": 9 } }
}
```

## 避坑

- 只有带 `session_id` 的聊天会写统计；不传 session_id 的裸流式调用不统计。
- 统计写入失败不应影响聊天，建议包 try/except。
- `duration_ms` 包含 Embedding/记忆写入时间，分析模型耗时时要留意。
