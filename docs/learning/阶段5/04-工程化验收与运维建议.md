# 04 · 工程化验收与运维建议

## 做了什么

阶段 5 收口了工程化基础：

- 模型按表配置、官方/中转双模式
- chat 限流 + 流式重试
- `model_calls` 统计 + `/api/stats`
- 沿用 Loki/Grafana 观测日志

## 为什么

功能再多，没有稳定性和可观测性就不能上线。这一阶段把“能跑”变成“能排查、能防刷、能统计”。

## 运维建议

### 日志

- 继续用 `docker compose logs -f backend` 和 Grafana Live Tail。
- 生产环境建议给 Loki 配置保留期，避免磁盘打满。

### 统计

- 用 `/api/stats` 或直接查 `model_calls` 表。
- 告警关注：成功率低于 95%、失败集中在某个模型、Token 突增。

### 安全

- 生产环境 `RATE_LIMIT_PER_MINUTE` 适当调低，并加登录鉴权。
- API Key 必须用 Fernet 密文 + 环境变量注入，不能进 git。

## 验收命令

```powershell
cd backend; .\venv\Scripts\python.exe -m pytest -q
cd frontend; pnpm build
Invoke-RestMethod http://localhost:8000/api/stats
```

## 避坑

- 限流、重试、统计都是单机实现，多实例部署时需要换成 Redis 等共享方案。
- 统计的 Token 是估算值，财务对账前请接入精确 usage。
- 日志量会随逐段 delta 日志增长，生产可加采样或保留策略。
