# 03 · 多租户数据隔离

## 做了什么

会话、消息、文档、记忆全部改为按 `user_id` 隔离：

- sessions API 使用当前用户 ID。
- documents API 使用当前用户 ID。
- chat 保存消息/记忆时绑定当前用户。
- 检索记忆/文档时只搜当前用户数据。

## 为什么

多租户的核心是“数据不能串”。所有查询和写入都从“默认用户”改成“当前登录用户”，接口返回 404 而不是泄露别人数据。

## 原理

### 服务层显式传 user_id

```python
def list_sessions(db, user_id: int):
    return session_repo.list_sessions(db, user_id)
```

接口层从 `get_current_user` 拿用户，再传给服务层：

```python
@router.get("")
def list_sessions(user: User = Depends(get_current_user), db=Depends(get_db)):
    return ok({"sessions": session_service.list_sessions(db, user.id)})
```

### 越权访问

`get_session(db, session_id, user_id)` 同时过滤用户，别人会话返回“不存在”（404），不泄露存在性。

## 命令解释

```powershell
$headers = @{ Authorization = "Bearer <access_token>" }
Invoke-RestMethod -Uri http://localhost:8000/api/sessions -Headers $headers
```

## 避坑

- 忘记在查询加 `user_id` 过滤就是越权漏洞。
- 返回 404 而不是 403，避免暴露资源是否存在。
- 记忆/向量 payload 里也要带 `user_id`，否则 Qdrant 检索会串数据。
