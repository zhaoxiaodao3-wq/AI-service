# 05 · 前端上传与知识库问答联调

## 做了什么

前端完成两块：

- 上传页 `/upload`：点击或拖拽上传 PDF/TXT/MD，展示已上传文档列表，支持删除。
- 聊天页 `/chat`：输入区新增“知识库”开关，开启后请求带 `use_rag: true`。

## 为什么

后端能力已经齐全，前端需要把这些能力包装成用户能直接用的操作：上传文件、看文档状态、一键切换“普通聊天 / 知识库问答”。

## 原理

### 上传流程

```text
选择文件 → FormData → POST /api/documents → 后端解析/切片/向量化 → 返回文档信息
```

`UploadView.vue` 用 `request.post('/documents', formData, { timeout: 120000 })`，因为后端要同步做 Embedding，耗时可能超过默认 30s。

### 聊天流程

```text
开启知识库 → chatStream(..., session_id, use_rag=true)
  → 后端检索并注入片段 → SSE 逐段返回 → 打字机显示
```

`chatStream.ts` 的 payload 结构：

```ts
{
  messages,
  model,
  session_id,
  use_rag: true
}
```

## 命令解释

```powershell
cd frontend
pnpm build
```

类型检查 + 打包，确认前端代码无编译错误。

```powershell
pnpm dev
```

本地开发服务，打开 http://localhost:5173，进入“文档上传”传一个 TXT，再去“聊天”打开知识库开关提问。

## 避坑

- 上传接口是异步执行向量化，文件越大等待越久；前端要有 loading 状态，避免用户重复点击。
- 删除文档要二次确认，同时后端要连 Qdrant 一起删，否则“文档没了但向量还在”。
- 知识库开关是当前请求级别的，切换会话不影响开关状态；如果想要每个会话记忆开关，放到阶段 4/5。
- 刷新页面后文档列表从 `GET /api/documents` 重新加载，不依赖前端内存。
