# 02 · 文本切片原理与实现

## 做了什么

`backend/app/services/chunker.py` 手写了一个简单切片器：

```python
def split_text(text, chunk_size=500, chunk_overlap=50):
    step = max(1, chunk_size - chunk_overlap)
    ...
```

它按固定窗口长度切文本，相邻片段保留 `chunk_overlap` 字符的重叠，避免把语义完整的句子从中间切断。

## 为什么

Embedding 模型和 LLM 都有上下文长度限制，而且“整个文档直接向量化”会让相似度被无关内容稀释。把文档切成小块后：

- 每个片段向量更聚焦，检索时能精准命中。
- 超长文档可以分多次处理。
- Prompt 里只塞最相关的几段，不浪费 token。

重叠的作用是**兜住边界语义**：如果一句关键信息恰好跨在两个片段之间，没有重叠它可能两半都不完整。

## 原理

### 固定窗口 + 步长

```text
chunk_size = 500
chunk_overlap = 50
step = 500 - 50 = 450

片段0: [0:500]
片段1: [450:950]
片段2: [900:1400]
```

`start` 每次前进 450，因此每个片段与上一个片段共享 50 字符。

### 为什么现在不做“按句切”

真正的生产级切片会先按段落/句子切，再合并到接近目标长度，避免把一句话拆开。本项目先用手写固定窗口，目的是理解“窗口 + 重叠”的底层机制；阶段 5 可以换 LangChain 或自研按句切片。

## 命令解释

```powershell
cd backend
.\venv\Scripts\python.exe -c "from app.services.chunker import split_text; print(split_text('abcdefghij', 5, 2))"
```

输出：`['abcde', 'defgh', 'ghij']`，可以看到第二个片段与前一个重叠了 `de`。

## 避坑

- `chunk_size` 必须大于 `chunk_overlap`，否则 `step` 会小于 1 导致死循环，代码用 `max(1, ...)` 兜底。
- 空片段要过滤，否则会生成无意义向量。
- 中文按字符数切片即可；英文建议按单词切，避免把单词劈成两半。
- 重叠越大检索越稳，但向量数量越多、存储越大，需要按效果调参。
